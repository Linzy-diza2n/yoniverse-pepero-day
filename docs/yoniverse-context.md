# 요니버스 서비스 맥락

> 스핀오프 프로젝트의 기획·디자인·개발 배경 자료. 2026-10-28 기준 저장소 문서와 앱 코드를 바탕으로 정리했다. 이 파일만 다른 프로젝트에 복사해도 읽을 수 있도록 구성했다. 기능 설명은 제품 구조와 저장소 기준이며, 모든 기능의 운영 출시를 의미하지 않는다.

## 1. 어떤 서비스인가

**요니버스(Yoniverse)는 연애 상황을 중심으로 콘텐츠를 읽고, 고민과 경험을 나누며, 다른 사람의 의견을 구하는 모바일 콘텐츠·커뮤니티 서비스다.**

사용자는 요매거진 콘텐츠를 읽거나, 자신의 상황에 맞는 커뮤니티에서 글과 댓글을 통해 대화한다. 짝사랑과 썸부터 연애 중 갈등, 이별과 재회, 결혼 고민까지 관계의 여러 순간을 다룬다.

현재 제품을 이해하는 핵심 축은 **편집 콘텐츠인 요매거진**과 **사용자가 참여하는 연애 커뮤니티**다. 연애 테스트와 오프라인 모임도 앱 구조에 등장하지만, 현재 확인한 코드에서는 준비 화면이다.

## 2. 사용자와 이용 맥락

제품의 주제와 기능에서 읽을 수 있는 주요 이용 맥락은 다음과 같다. 특정 연령·성별의 시장 규모나 사용자 통계를 뜻하지 않는다.

- 자기 연애 상황을 이해하는 데 도움이 되는 글을 읽고 싶은 사람.
- 주변 사람에게 쉽게 꺼내기 어려운 고민을 나누고 싶은 사람.
- 상대의 행동이나 관계의 다음 선택에 대해 다른 관점을 듣고 싶은 사람.
- 비슷한 경험을 가진 사람의 이야기를 읽고, 자기 경험으로 답하고 싶은 사람.

예를 들면 “이 관계를 더 이어가도 될까?”라는 고민을 관련 콘텐츠로 탐색하고, 커뮤니티에 상황을 설명한 뒤 댓글이나 투표로 의견을 받는 흐름이다. 이는 제품 이해를 위한 이용 예시이며 실제 사용자 사례가 아니다.

## 3. 핵심 서비스 구성

| 영역 | 역할과 주요 경험 |
| --- | --- |
| 홈 | 매거진과 커뮤니티 글을 발견하고 상세 콘텐츠로 들어가는 출발점 |
| 요매거진 | 운영 측이 제공하는 콘텐츠를 목록과 상세 화면에서 읽는 영역 |
| 커뮤니티 | 연애 상황별 게시판에서 글을 읽고 작성하며 댓글·좋아요·투표로 참여하는 영역 |
| 검색 | 관심 있는 주제와 콘텐츠를 찾는 진입점 |
| 마이 | 프로필·내 활동·계정·알림 설정 등을 관리하는 영역 |
| 알림 | 활동 관련 알림을 모아 확인하고 서비스로 돌아오는 접점 |

현재 앱의 주요 하단 탐색 구조는 홈·커뮤니티·마이다. 세부 기능에는 회원 상태와 이용 권한에 따른 접근 처리가 있으며, 카카오·Apple 로그인 연동 코드가 있다.

### 커뮤니티의 주제

앱의 카테고리 모델은 다음 일곱 가지 상황을 다룬다.

1. 썸/소개팅
2. 짝사랑
3. 연애중
4. 재회
5. 이별/권태기/장기연애
6. 연애 잡담
7. 결혼 고민

이 구분은 요니버스가 단일 연애 단계에만 집중하지 않고, 관계의 시작·유지·종료와 이후 고민을 함께 다룬다는 점을 보여준다.

### 참여 방식과 정책 맥락

- **글과 댓글:** 개인의 상황을 설명하고 다른 사용자의 경험·의견을 받는 기본 단위다.
- **좋아요:** 게시글과 댓글에 반응하는 수단이다.
- **투표:** 게시글에 선택지를 붙여 의견을 모은다. 현재 확정 계약은 선택지 2~10개, 회원 참여, 제출 후 변경·취소 불가, 참여 후 결과 공개다. 목록에서는 미리보기를 보고 상세에서 제출한다.
- **답글:** 댓글에 1단계 답글을 연결하는 확장이다. 서버 구현 기록은 있으나 앱 연동·실기기·운영 검증 상태는 따로 관리된다.
- **닉네임:** 랜덤닉네임 안내가 있지만 실제 정책은 게시판별로 구분된다. 모든 영역에서 동일한 익명성이나 글별 닉네임 정책이 보장된다고 일반화하면 안 된다.
- **신고와 차단:** 욕설·비방, 선정적 내용, 광고·도배, 개인정보 노출 등에 대응하기 위한 신고와 사용자 차단 구조가 있다.

## 4. 서비스의 성격을 어떻게 이해하면 좋은가

다음은 현재 서비스 구성에서 도출한 제품 해석이다.

**콘텐츠와 대화가 함께 있다.** 운영 측의 글을 읽는 경험과 사용자끼리 자기 이야기를 주고받는 경험이 연결된다. 스핀오프에서도 콘텐츠 소비와 사용자 참여 중 어디에 무게를 둘지 구분하는 것이 유용하다.

**연애의 상황이 탐색 기준이다.** 추상적인 관계 정보보다 “지금 내가 겪는 상황”을 통해 들어갈 수 있는 구조다. 카테고리와 콘텐츠의 표현도 이 맥락에서 이해할 수 있다.

**개인적인 이야기를 다루는 커뮤니티다.** 닉네임 노출, 신고·차단, 삭제·숨김 상태와 같은 정책이 사용자 경험에 직접 영향을 준다. 스핀오프에서 실제 사용자 콘텐츠를 연결한다면 이러한 정책도 별도로 설계해야 한다.

## 5. 디자인 맥락

현재 앱은 텍스트와 콘텐츠 목록, 게시글 상세, 댓글, 입력 화면을 중심으로 구성된다. 기존 디자인 토큰에는 브랜드 포인트 색상 `#FF385C`, 주요 본문 색상 `#212121`, 연한 회색 배경과 경계선이 사용된다.

스핀오프에서 이어받을 수 있는 시각적 단서는 다음과 같다. 이는 기존 서비스와의 연결감을 위한 참고이며 새 프로젝트의 확정 디자인 규칙은 아니다.

- 읽기 쉬운 본문과 명확한 정보 위계.
- 상황을 바로 알아볼 수 있는 친숙한 한국어 표현.
- 주요 행동이나 선택 상태에 사용하는 브랜드 포인트 색상.
- 글을 읽고 의견을 남기는 흐름을 방해하지 않는 화면 구성.

정확한 컴포넌트·색상·간격은 원본 앱의 테마와 공통 UI가 기준이다. 요니버스의 모든 화면을 스핀오프에 그대로 복제할 필요는 없다.

## 6. 현재 기능과 확장 아이디어의 구분

| 항목 | 이 문서에서의 취급 |
| --- | --- |
| 매거진·커뮤니티·프로필·검색·알림 | 현재 저장소에 기능 코드가 있는 핵심 구성 |
| 투표 | 앱·서버 구현 기록과 확정 계약이 있으며, 실기기·운영 반영 확인은 별도 |
| 댓글 답글 | 서버 완료 기록과 앱 작업이 존재하며, 통합·검증 범위는 별도 확인 필요 |
| 연애 테스트 | 현재 앱 코드에서는 준비 화면 |
| 오프라인 모임 | 현재 앱 코드에서는 준비 화면 |
| 커뮤니티 보상·댓글 채택·레벨·칭호 | 기획 논의가 있으며 확정 정책과 미정안을 구분해야 하는 영역. 출시된 시스템으로 전제하지 않음 |

AI 상담, 상대 매칭, 유료 구독 등은 이 문서에서 현재 핵심 기능으로 확인한 범위에 포함되지 않는다. 스핀오프에 도입할 경우 새 프로젝트의 제안으로 다뤄야 한다.

## 7. 기술 구성과 기존 서비스 연결

요니버스는 하나의 저장소에서 다음 구성 요소를 관리한다.

| 구성 요소 | 기술·역할 |
| --- | --- |
| 모바일 앱 | Flutter·Dart, Riverpod 상태 관리, go_router 화면 이동, Dio API 통신 |
| 사용자 API | Java 17·Spring Boot 기반의 앱용 서버 |
| 관리자 API | 별도 빌드·배포하는 관리용 서버 |
| 데이터베이스 | PostgreSQL |
| 관리자 웹 | Next.js·React |
| 앱링크 | 공유 링크와 앱 화면 연결을 위한 별도 정적 프로젝트 |
| 푸시 | Firebase Cloud Messaging 기반 알림 연동 |

이 구성은 기존 서비스의 맥락이며 스핀오프의 기술 선택을 제한하지 않는다. 기존 계정·게시글·콘텐츠·API를 공유할지는 별도의 제품·기술 결정이다. 연결을 선택한다면 인증·접근 권한·닉네임 노출·데이터 사용 범위와 기존 앱 호환성을 먼저 확인해야 한다.

## 8. 스핀오프 프로젝트에서 활용하는 방법

이 문서는 요니버스의 배경을 설명한다. 스핀오프의 목표·대상 사용자·기능·사업 모델은 아직 정하지 않는다. 새 프로젝트에서는 다음 사항을 별도 기획으로 명시하면 된다.

- **해결할 문제:** 요니버스의 어떤 이용 상황을 더 깊게 다룰 것인가.
- **핵심 경험:** 콘텐츠 읽기, 고민 공유, 자기 이해 등 무엇을 중심에 둘 것인가.
- **브랜드 관계:** 요니버스 이름과 시각 요소를 어느 정도 이어받을 것인가.
- **서비스 연결:** 독립 서비스인지, 기존 계정·콘텐츠·커뮤니티와 연결할 것인지.
- **첫 출시 범위:** 기존 기능 중 무엇을 활용하고 어떤 기능을 새로 만들 것인지.

### 다른 프로젝트의 AI·협업자가 읽을 때

요니버스는 연애 상황별 콘텐츠와 커뮤니티가 중심인 서비스로 이해한다. 기존 기능, 준비 중 화면, 기획 아이디어를 구분하고, 스핀오프의 새 아이디어를 요니버스의 확정 정책이나 출시 기능으로 취급하지 않는다. 구체적인 API 재사용이나 데이터 연결은 최신 계약을 확인한 뒤 결정한다.

## 9. 원본 확인 경로

아래 경로는 `yoniverse-monorepo` 저장소 루트 기준의 참고 위치다. 파일을 다른 프로젝트로 옮겨도 본문은 독립적으로 사용할 수 있다.

- `docs/product.md`: 제품 범위와 확정 정책 참조.
- `docs/design-system.md`: 디자인 기준과 후속 결정.
- `docs/architecture.md`: 기술 구조와 API 계약 위치.
- `docs/handoff.md`: 진행 중 항목과 실기기·운영 후속 상태.
- `yomagazine_app/README.md`: 앱 소개와 기술 구성.
- `yomagazine_app/lib/features/`: 실제 기능별 앱 코드.

외부 기획 원본으로 안내된 `../yo-magazine`은 작성 시점의 로컬 위치에서 찾을 수 없어 본문 근거에 포함하지 않았다. 사용자 수·매출·시장 규모·정확한 고객 인구통계·수익 모델은 확인된 자료가 없어 기재하지 않았다.
