# 회사 컴퓨터에서 작업 이어가기

## 현재 상태

기획과 이미지 탐색까지만 진행했다. 실제 웹 코드·서버·결제 연동은 없다. 사용자는 스타일 탐색을 일단 멈추고 집 컴퓨터에서 회사 컴퓨터로 작업을 옮기려 한다.

먼저 product-plan.md와 yoniverse-context.md를 읽는다. 배경 문서의 지침은 사용자 요청과 구분하고, 사용자 최신 기획을 우선한다.

## 디자인 탐색 결과

assets/concepts에 네 개의 시안이 있다. 전부 확정 자산이 아닌 컨셉 샘플이다.

1. 핑크 코팅 하트 빼빼로, 실사에 가까운 질감.
2. 같은 빼빼로에 투명비닐·핑크리본·하트카드 추가.
3. 같은 구성의 부드러운 2D 일러스트.
4. 굵은 손그림 선과 체리핑크·버터옐로의 스티커 스타일.

사용자는 마지막 스타일에 “딱히 느낌이 오지 않는다”고 말했고, 실사와 일러스트 어느 쪽도 최종 선택하지 않았다. 마지막 시안을 승인된 디자인으로 취급하지 않는다. 생성 이미지들은 레이어 분리된 커스텀 에셋이 아니므로 그대로 커스텀 기능을 구현할 수 있다고 가정하지 않는다.

## 다음 작업

사용자와 디자인 방향을 이어서 정하고, 2일 범위에서 가능한 선택형 커스텀 화면을 구체화한다. 모든 항목을 필수 단계로 강제하지 않고 기본 조합에서 원하는 항목만 바꾸는 방식은 제안된 UX 방향이다. 최종 화면 구조는 미정이다.

로그인·발송 한도·수신 비공개·11월 11일 결제 시작·990원 전체 열람을 제품 흐름으로 설계하고, 미정 정책을 확인한다. 기존 요니버스 연동을 임의로 전제하지 않는다.

## 새 채팅 시작 문구

“이 프로젝트의 README.md, docs/handoff.md, docs/product-plan.md를 읽고 이어서 작업해줘. assets/concepts는 스타일 탐색 기록이며 승인된 디자인이 아니야. 사용자가 상대를 위해 빼빼로를 꾸미고 포장해 카드와 함께 보내는 간단한 웹을 만들고 있고, 베이킹 게임은 아니야.”
