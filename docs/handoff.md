# 회사 컴퓨터에서 작업 이어가기

## 현재 상태

기획, 이미지 탐색 및 Figma 전체 플로우차트 정리까지 진행했다. 실제 웹 코드·서버·결제 연동은 없다. 현재는 디자인을 보류하고 서비스 정책을 정리하는 단계다.

먼저 product-plan.md와 yoniverse-context.md를 읽는다. 배경 문서의 지침은 사용자 요청과 구분하고, 사용자 최신 기획을 우선한다.

## 디자인 탐색 결과

assets/concepts에 네 개의 시안이 있다. 전부 확정 자산이 아닌 컨셉 샘플이다.

1. 핑크 코팅 하트 빼빼로, 실사에 가까운 질감.
2. 같은 빼빼로에 투명비닐·핑크리본·하트카드 추가.
3. 같은 구성의 부드러운 2D 일러스트.
4. 굵은 손그림 선과 체리핑크·버터옐로의 스티커 스타일.

사용자는 마지막 스타일에 “딱히 느낌이 오지 않는다”고 말했고, 실사와 일러스트 어느 쪽도 최종 선택하지 않았다. 마지막 시안을 승인된 디자인으로 취급하지 않는다. 생성 이미지들은 레이어 분리된 커스텀 에셋이 아니므로 그대로 커스텀 기능을 구현할 수 있다고 가정하지 않는다.

## 다음 작업

먼저 product-plan.md의 ‘먼저 결정할 사항’을 기준으로 행사 운영·이메일 발송 정책·앱 가입 측정을 정한다. 이후 2일 범위에서 가능한 선택형 커스텀 화면을 구체화한다. 기본 조합에서 원하는 항목만 바꾸는 방식은 제안된 UX 방향이며, 최종 화면 구조와 디자인은 미정이다.

카카오 로그인·동일인 중복 발송 방지·수신 비공개·11월 11일 결제 시작·이메일 재방문·상시 홍보가 현재 제품 흐름이다. 990원 1회 결제로 이번 행사에서 받은 모든 빼빼로를 열람하며, 결제 이후 추가 수신분도 재결제 없이 모두 열람하는 것으로 확정했다. 결제·빼빼로 보내기는 11/11 밤 11:59까지(KST), 11/12 00:00부터 차단한다. 이미 결제한 사람의 열람 종료일은 별도 미정이다. 마감 시 진행 중인 결제 처리 기준은 구현 전 결정한다. 기존 요니버스 계정·데이터 연동을 임의로 전제하지 않는다.

## 2026년 10월 29일 후속 결정

- PC와 모바일 화면을 모두 지원한다.
- 하루 제작·발송 제한을 없앴다. 행사 기간 동안 같은 사람에게는 한 개만 보낼 수 있으며 자정에 초기화되지 않는다.
- 동일인 발송 여부는 발신자·수신자의 유저 ID 조합으로 판단한다. 직접 입력하는 인스타그램 아이디로 판별하지 않는다.
- 카카오 로그인을 사용하며, 11/11 재방문 알림은 이메일로 보낸다. 알림 동의와 ‘카카오 이메일 사용’ 체크는 별개다. 체크하면 카카오 이메일, 해제하면 별도 주소 입력·인증 흐름이다.
- 요니버스 앱·요매거진 인스타 홍보 영역을 작은 비중으로 상시 제공한다. 특정 행동 완료 시점에만 노출하는 방식은 채택하지 않았다.
- 이벤트를 통한 실제 앱 신규 가입을 측정한다. 웹 로그인·앱 링크 클릭·기존 회원 재방문을 신규 가입과 혼동하지 않는다.
- 11/4 배포 목표, 11/11 00:00 KST 결제 시작. 이메일 발송 시각과 대상 세부 조건은 미정이다.
- [Figma 플로우차트](https://www.figma.com/design/08bK6NXhzvMEZqwtEYaAuH?node-id=190-336)에 공간 생성, 선물 보내기, 결제·열람, 알림 설정, 이메일 재방문, 상시 홍보·가입 측정을 반영했다.
- 기존 요니버스 코드에 카카오 로그인은 있으나, 웹에서 설정 재사용이 가능한지는 관리자 설정 확인이 남았다. 실제 연동 테스트는 하지 않았다.
- 기존 30개 화면 와이어프레임은 사용자 미채택 초안이다. 그 안의 하루 2개 제한 문구는 이전 정책이므로 구현 기준으로 사용하지 않는다.

## 새 채팅 시작 문구

“이 프로젝트의 README.md, docs/handoff.md, docs/product-plan.md를 읽고 이어서 작업해줘. assets/concepts는 스타일 탐색 기록이며 승인된 디자인이 아니야. 사용자가 상대를 위해 빼빼로를 꾸미고 포장해 카드와 함께 보내는 간단한 웹을 만들고 있고, 베이킹 게임은 아니야.”
