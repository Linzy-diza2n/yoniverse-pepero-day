# 회사 컴퓨터에서 작업 이어가기

## 현재 상태

기획, 이미지 탐색 및 Figma 전체 플로우차트 정리까지 진행했다. 실제 웹 코드·서버·결제 연동은 없다. 현재는 디자인을 보류하고 서비스 정책을 정리하는 단계다.

먼저 product-plan.md와 yoniverse-context.md를 읽는다. 배경 문서의 지침은 사용자 요청과 구분하고, 사용자 최신 기획을 우선한다.

## 디자인 탐색 결과

assets/concepts에 네 개의 시안이 있다. 전부 확정 자산이 아닌 컨셉 샘플이다.

1. 핑크 코팅 하트 빼빼로, 실사에 가까운 질감.
2. 같은 빼빼로에 투명비닐·핑크리본·하트카드 추가.
3. 같은 구성의 부드러운 2D 일러스트.
4. 굵은 손그림 선과 체리핑크·버터옐로의 스티커 스타일.

사용자는 마지막 스타일에 “딱히 느낌이 오지 않는다”고 말했고, 실사와 일러스트 어느 쪽도 최종 선택하지 않았다. 마지막 시안을 승인된 디자인으로 취급하지 않는다. 생성 이미지들은 레이어 분리된 커스텀 에셋이 아니므로 그대로 커스텀 기능을 구현할 수 있다고 가정하지 않는다.

## 다음 작업

먼저 product-plan.md의 ‘먼저 결정할 사항’을 기준으로 행사 운영·이메일 발송 정책·앱 가입 측정을 정한다. 이후 2일 범위에서 가능한 선택형 커스텀 화면을 구체화한다. 기본 조합에서 원하는 항목만 바꾸는 방식은 제안된 UX 방향이며, 최종 화면 구조와 디자인은 미정이다.

카카오 로그인·동일인 중복 발송 방지·수신 비공개·11월 11일 결제 시작·이메일 재방문·상시 홍보가 현재 제품 흐름이다. 990원 1회 결제로 이번 행사에서 받은 모든 빼빼로를 열람하며, 결제 이후 추가 수신분도 재결제 없이 모두 열람하는 것으로 확정했다. 결제·빼빼로 보내기는 11/11 밤 11:59까지(KST), 11/12 00:00부터 차단한다. 이미 결제한 사람의 열람 종료일은 별도 미정이다. 마감 시 진행 중인 결제 처리 기준은 구현 전 결정한다. 기존 요니버스 계정·데이터 연동을 임의로 전제하지 않는다.

## 발신자 소개 추가 (2026-10-30)

사용자 요청으로 로그인 전 랜딩에 이름 공개·익명 발송 선택을 소개하는 영역과 편지 예시를 추가했다. 실제 발송 기능은 아직 미연결이다. 기존 인스타그램 아이디 필수 입력 기획과 함께 정리해야 하며, 구현 시 수신자에게 발신자 표시를 공개할지 선택하도록 반영해야 한다. 익명 표시는 비로그인 발송이나 운영 시스템의 신원 미수집을 뜻하지 않는다.

## 학교별 참여 현황 시안 (2026-10-30)

로그인 후 캐비넷 화면(index.html)에 학교 선택 카드와 검색 다이얼로그를 추가했다. school.js / school.css에서 관리한다. 학년은 수집하지 않는다. 이름과 지역을 함께 표시하고 학교 ID만 브라우저에 저장한다. 저장을 반복해도 중복 증가하지 않으며 학교 변경과 재방문을 지원한다.

현재 로그인·서버가 없는 시안이므로 예시 학교 5개만 검색된다. 인원은 선택한 학교의 내 참여 1명만 표시하며 미리보기임을 명시했다. 목표 20명은 참고 이미지 기반 임시값이며 추첨 정책은 확정하지 않았다. 실제 서비스에서는 공식 학교 목록 검색, 로그인 사용자별 학교 저장, 학교 ID별 중복 없는 참여자 집계 API로 교체해야 한다. 로그인 성공 후 이 캐비넷 화면으로 연결하고, 타인의 참여 수는 서버에서 조회해야 한다. 이 시안의 localStorage를 실제 인증 또는 전체 참여 집계로 사용하지 않는다.

### 학교 선택 진입 순서 및 비학생 (2026-10-30)

첫 캐비넷 진입(로그인 후 목적지의 시안)에서 저장된 선택이 없으면 학교 선택 창을 먼저 연다. 최초 선택은 학교 저장 또는 ‘학생이 아니에요’로 완료하며, 재방문은 저장된 선택으로 바로 캐비넷을 보여준다. 저장 직후 참여 카드를 화면에 표시한다. 비학생은 학교 집계·목표를 숨기고 작은 학교 등록 안내만 표시한다. 비학생 상태도 저장하며 추후 학교 등록으로 변경할 수 있다. 실제 인증은 여전히 미연결이다.

### 학교 이벤트 문구 수정 (2026-10-30)

목표 인원 20명은 확정되지 않았다. 기존 임시값 대신 ‘nn명’으로 표시하며 목표가 미정인 동안 비율 진행 막대는 표시하지 않는다. 학교 선택과 캐비넷 이벤트 안내에 ‘우리 학교 친구들이 nn명 이상 모이면 추첨을 통해 막대과자 선물을 쏠게요!’를 반영했다. ‘학년은 입력하지 않아요’ 설명은 삭제했다. 학년 미수집 동작은 유지한다.

### 학교 자동완성 (2026-10-30)

빈 검색창에서는 목록을 숨기며 입력할 때마다 학교 이름/별칭에 일치하는 목록을 표시한다. 선택 시 정식 학교 이름을 채우고 지역 선택을 안내한다. 방향키·Enter 선택과 Escape 목록 닫기를 지원하며 한글 조합 중 Enter는 선택으로 처리하지 않는다. 검색어 수정 시 이전 선택을 해제한다. 예시 학교 목록 범위는 그대로이며 전국 학교 검색은 서버 연동 필요.

## GNB 계정 메뉴 (2026-10-30)

상단 원형 버튼은 꾸미기 대신 작은 계정 팝오버를 연다. 카카오 로그인 수단과 로그아웃을 표시하며, 실제 계정 연결 전 시안임을 명시한다. 바깥 클릭과 Escape로 닫히는 native popover를 사용한다. 현재 로그아웃은 랜딩으로 이동만 하며 학교 선택·꾸미기 데이터는 지우지 않는다. 실제 인증 연결 시 서버 세션 무효화가 성공한 후 이동하도록 account.js를 연결해야 한다. 이름표와 꾸미기 버튼을 통한 편집은 유지한다.

## 운영 화면 기준 디자인 (2026-10-30)

사용자는 화면을 항상 오픈한 서비스 상태로 디자인하도록 요청했다. 학교 카드와 선택 창에서 미리보기·실제 집계 전·예시 학교 설명을 제거했다. 기술적 미연결 사항은 사용자용 화면이 아닌 인계 문서에서 관리한다. 학교명과 쉐브론 버튼으로 변경 창을 열며 별도 대형 변경 버튼은 제거했다. 참여 수/목표 아래 프로그레스바를 표시한다. 목표는 여전히 nn명으로 미정이며 현재 채움 8%는 디자인용 값이다. 운영 연동 시 확정 목표와 실제 참여 수의 비율로 교체해야 한다.

## 학교 선택은 선택 사항 (2026-10-30)

학교 등록은 로그인·선물 전송의 필수 조건이 아니다. 선물 발신 중 카카오 로그인 후에는 작성한 선물 전송으로 복귀하고 학교 선택으로 우회시키지 않는다. 내 캐비넷의 최초 학교 선택 제안도 ‘나중에 선택하기’·닫기·Escape로 건너뛸 수 있다. 건너뛰기는 비학생 선택과 별도로 저장하며, 캐비넷 카드에서 언제든 학교를 등록할 수 있다. 미등록 사용자는 학교 인원 집계에서 제외한다. 실제 로그인 콜백 연동 시에도 학교 등록 여부로 선물 전송을 차단하지 않는다.

## NEIS 연결 준비 (2026-10-30)

예시 목록을 제거하고 `/api/schools?q=` 비동기 검색으로 교체했다. `python3 server/run.py`가 정적 파일과 NEIS 프록시를 4174에서 제공한다. 사용자는 인증키가 아직 없다고 답했다. `.env`의 NEIS_API_KEY 설정 후 재시작해야 실제 검색이 가능하다. 학교 ID는 교육청+학교코드로 통일하며 기존 예시 선택은 다시 선택해야 한다. 서버 집계 모듈은 준비했으나 실제 로그인 서버가 없어 호출하지 않는다. 현재 브라우저 학교 선택 저장을 실제 서버 등록으로 오인하면 안 된다. 전체 참여자 수를 알 수 없어 기존 고정 1명과 임의 8% 채움은 제거했다. 인증 연결 이후 서버에서 학교 ID를 검증하고 로그인 계정 기준 Memberships.select를 호출하며 공개 집계 엔드포인트를 연결해야 한다.
